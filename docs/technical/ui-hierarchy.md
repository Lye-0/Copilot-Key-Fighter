# 設定UIの階層と操作の関係

2026-09-15 のユーザーレビューを反映した、現在の設定画面の構成。

|関係|画面での表現|
|---|---|
|アプリ全体に作用する設定|有効化とログイン時起動を、動作選択の上にある「全体設定」領域へまとめる|
|3つから1つを選ぶ排他的な動作|共通トラックと1つの選択位置を持つセグメント切り替え。独立した実行ボタンとして見せない|
|同じ対象を選ぶ並列の方法|アプリ一覧からの選択とファイル選択を、同じ行・同じ大きさで隣接させる|
|選択した対象を使った実行|起動テストを同じ行の右側へ離し、選択操作と区別する|
|同時に成立するキーの組み合わせ|複数選択の修飾キースイッチとメインキーを、同じ行で「＋」につなぐ|
|設定内容の要約|「送信する操作」という見出しの下に組み合わせを表示。変換方向の矢印を置かず、矢印キーの記号との連続を防ぐ|
|展開見出しとその従属内容|見出し行と本文が一体になったアコーディオン。見出しだけを枠付きボタンにせず、区切り線と共通背景でつなぐ|
|現在適用済みの情報|製品名の下に読み取り専用で表示。ヘッダーは行の高さでレイアウトし、固定座標で文字を重ねない|

## 実装と検証

SettingsForm に全体設定、対象選択、キー構成の各領域を設ける。ModeSelector は RadioButton の排他選択を保ち、UiCheck は必要に応じて独立したトグルとして描画する。

AccordionSection は見出しと本文を同じコンテナーで管理する。見出しは本文の開閉だけを行い、矢印を右端の専用領域に描く。展開した内容は独立したスクロール用 Panel 内の自動サイズのレイアウトに収め、保存領域は画面下端に残す。

UIテストでは、全体設定のまとまり、メインキーと修飾キーの同じ行への配置、要約とアコーディオンの非重複、開閉による高さ変更、展開時のスクロール、保存の状態管理を確認する。PaintTests は新しいトグルとアコーディオン見出しにも黒い塗り残りのチェックを適用する。

この判断基準は、後続のUIスキル作成時の参照資料として利用できる。現時点ではプロジェクトのUI設計を記録した文書であり、グローバルなスキル自体を作成・変更したものではない。

# Copilot Key Fighter 配布版 開発計画

作成日: 2026-09-14

状態: 計画。以下の配布版機能は未実装。既存の個人用 ChatGPTLauncher の稼働環境は、この計画作成では変更しない。

## 目標と初版の範囲

Windows 11 x64 上で Copilot キーの標準動作を抑止し、ユーザーが選んだアプリ起動、キー入力、または何もしない動作へ割り当てる。PowerToys、AutoHotkey、外部常駐ソフトに依存しない。

初版は .NET 10 / WinForms を継続し、self-contained / single-file の `CopilotKeyFighter.exe` を GitHub Releases の ZIP で配布する。Copilot 入力は既存の Left Win + Left Shift + F23 を最初の対応対象とする。他機種の異なる入力方式は診断・検証を経て追加する。

「キー割り当て」は通常キー、ファンクションキー、メディアキー、修飾キーを含むショートカットを対象とする。初版は1操作につき1回の押下・解放で、押し続けるリマップやマクロは含めない。修飾キー単独を保持する割り当て、自己再帰する Copilot 入力、Ctrl+Alt+Delete のような保護された操作は対象外として設定時に説明する。

## 既存実装の確認と再利用

指定リポジトリは main ブランチ、コミットなし。origin は `https://github.com/Lye-0/Copilot-Key-Fighter.git`。この計画時点ではリモートの読み書きは行っていない。

現在の個人用ソースを読み、次の構成を確認した。移植対象のハッシュは `docs/plans/legacy-source-manifest.json` に記録する。

|既存の構成|配布版での扱い|
|---|---|
|CopilotGesture / KeyboardHook|F23 のみを選択的に抑止する状態機械と専用メッセージスレッドを再利用|
|Program / Resident|単一起動、通知領域、終了経路を再利用し、設定画面と動作分岐を追加|
|ChatGpt|固定 AUMID・パッケージ名を取り除き、対象解決・起動・ウィンドウ検索・前面化へ分離|
|ForegroundHotkey|既存の前面化経路を回帰試験の基準として維持し、一般アプリでの成立条件を検証|
|Assets/App.ico|採用済みのキー本体だけのアイコンを継続使用|
|状態機械のテスト|移植後に再実行し、キー送信と設定の試験を追加|

既存の検証記録には実キーによる背面・最小化からの復帰成功がある。一方、一般アプリ、他の Windows 環境、配布手順は未検証。内部通知方式の VK_NONAME と WM_HOTKEY は、この実装で利用している手段であり、あらゆるアプリに対する前面化保証として扱わない。登録競合・通知未到着時に待機状態が固定されないようにする。

## アプリの指定と起動

- 「インストール済みアプリから選ぶ」で名前・アイコンを一覧表示する。Windows Shell のアプリ一覧とプロパティから識別情報を取得し、通常操作ではユーザーに ID の調査を求めない。
- パッケージアプリは AUMID を保存し、IApplicationActivationManager で起動する。詳細欄では取得済み ID の確認・手動指定も可能にする。
- 通常のデスクトップアプリは実行ファイルの選択を用意し、絶対パス・引数・作業フォルダーを保存する。AUMID をすべての exe に必須とはしない。
- 一覧の項目は起動方式ごとに分類する。Shell 登録の ID があるだけで、すべてをパッケージ起動 API に渡さない。必要な Shell 起動は API 経由とし、PowerShell、cmd、explorer.exe を中継プロセスとして起動しない。
- 実行前に設定対象の存在・登録状態を確認する。アンインストールやパス変更は設定画面から修正できる。
- 「既存ウィンドウを優先」を既定とする。AUMID・プロセスの実行ファイルパス等から候補を特定し、前面なら維持、最小化なら復元、背面なら前面化する。タイトルだけやパッケージファミリーだけで別アプリを選ばない。
- 子プロセス、共通ホスト、複数ウィンドウを扱うため、起動対象の識別とウィンドウ所有プロセスを分けて設計する。候補は直近に使用されたウィンドウを優先する。
- ウィンドウが見つからない場合に起動する。連打中の起動をまとめ、起動待ちには期限を設ける。前面化だけが失敗した場合に再起動を繰り返さない。
- ウィンドウを持たないツールや独自ランチャーには「毎回起動」も選択可能にする。あらゆる外部アプリの多重起動防止を保証せず、対応確認済みの方式と制限を明示する。

## キー入力と安全性

- フック内では入力判定と軽い通知だけを行い、待機、アプリ検索、ファイル操作、設定画面の処理をしない。
- Copilot と判定した F23 の down / repeat / up だけを抑止する。物理 Win / Shift / Ctrl / Alt の down / up は常に通す。
- キー割り当ては Copilot 操作の F23 と物理修飾キーの解放を確認してから送る。Win+Shift が割り当て先のキーに混ざることを防ぐ。解放待ちはイベント駆動と期限付き再確認で実装し、常時ポーリングしない。
- 待機中の別操作、設定変更、無効化、終了、期限切れでは保留入力を取り消し、後から予期せず送信しない。連打のキューも無制限に蓄積しない。
- SendInput に固有タグを付けて自己入力を識別する。注入入力を再び Copilot 操作として処理しない。キーコード、拡張キー、キーボード配列を扱う。
- 注入したキーだけについて down/up の対応を管理し、失敗・部分送信・終了時の回復を用意する。物理的に押されている修飾キーを勝手に解放しない。入力開始直前の再確認と途中の物理入力との競合を重点試験する。
- SendInput は既存のキー状態をリセットせず、権限の高いアプリへの注入にも制限がある。通常権限を初版の基準とし、管理者画面や保護された画面を対応済みと扱わない。

## 設定と常駐の操作

初回は設定画面を開く。設定・有効化が完了するまでキーを横取りしない。画面は「アプリを開く」「キーを送る」「何もしない」の選択、対象指定、テスト、保存を中心とする。

通知領域メニューは「設定」「割り当てを実行（アプリ指定時）」「一時停止／再開」「終了」。キー送信のテストはメニューのクリック先へ誤送信しない専用の確認手順にする。

設定は `%LOCALAPPDATA%\CopilotKeyFighter\settings.json` に保存する。形式のバージョン、入力方式、割り当て種別、対象、ログイン時起動の希望を保持する。検証してから一時ファイル経由で置換し、破損時はキーを抑止せず設定の修正へ案内する。個人用のパスや設定を配布物に含めない。

ログイン時起動は設定画面のチェックから HKCU Run に登録する。管理者権限・サービス・タスクスケジューラーは不要。現在の exe の場所を登録し、移動後は起動時に自分の登録を更新する。解除も自分の項目だけを削除する。旧個人版との同時監視を検出し、移行時に旧版を終了してから新規有効化する。PowerToys の設定は変更しない。

## 実装順と完了条件

1. **移植と基準確保**: 既存ソース・採用アイコン・テストを `src/`、`tests/`、`assets/` へ整理。名称を統一し、ビルドと既存試験を通す。前面化と起動元から独立した常駐の回帰基準を残す。
2. **入力方式の検証**: 設定画面より先にキー送信の小さな試作を作る。F23／修飾キーの解放順、連打、自己再帰、部分送信、他のキーが混ざる場合を確認する。実機で stuck が起きないことを次工程の条件にする。
3. **アプリ起動の一般化**: アプリ一覧、ID 取得、exe 選択、起動と既存ウィンドウ優先を実装。ChatGPT、別のパッケージアプリ、通常 Win32 アプリ、複数ウィンドウのアプリで確認する。
4. **設定画面とライフサイクル**: 保存・読み込み・エラー回復、初回設定、トレイ、一時停止、自動起動を統合する。設定変更は再起動なしで適用する。
5. **配布検証**: .NET SDK がない Windows 11 のクリーン環境で ZIP 展開から起動・設定・再ログイン・終了・削除まで試す。旧版との移行も別に確認する。
6. **GitHub Releases**: Windows の CI でテストと発行を行い、バージョンタグから ZIP と SHA256 を生成する。初回はプレリリースのドラフトを作り、検証後に公開する。

推奨構成: `src/CopilotKeyFighter/`（入力・アプリ対象・設定・UI）、`tests/`、`assets/`、`docs/`、`.github/workflows/`、`agent-knowledge/`。小さなアプリとして責務を分け、外部フレームワークを不用意に追加しない。

## 検証表

|分類|必要な確認|
|---|---|
|自動テスト|既存の全状態機械試験、対象外入力の通過、解放順、長押し・連打、注入入力除外、送信失敗回復、設定検証・破損回復|
|アプリ|未起動、背面、最小化、既に前面、終了後の再起動、複数ウィンドウ、子プロセス、対象削除・移動、前面化拒否|
|キー|通常キー、Delete、F キー、メディア、Ctrl を含むショートカット、Win 系、JIS 配列、他キーとの同時入力、タイムアウト後の誤送信なし|
|実機入力|物理 Copilot キー、通常 Win / Shift / Ctrl、他ショートカット、連打後の stuck なし、Copilot／検索／スタートの同時起動なし|
|常駐|単一起動、アイドル CPU、スリープ復帰、ログイン時起動、終了時のフック解除、起動元終了後も生存|
|共存|PowerToys なしで動作、PowerToys の別リマップと共存、旧個人版との競合を防止|
|配布|SDK なし、パスに空白・日本語、設定の引き継ぎ、Run 登録解除、ZIP とハッシュ、秘密情報・個人パスの非混入|

自動試験と人による物理キー試験を分けて記録する。計測はキー検出から前面化確認までと、アプリのコールドスタートを分ける。現状の速さを維持することを目標とし、未計測の速度を保証しない。

## 公開前に決める事項

- 配布ライセンス。ソース公開と再利用許諾を明文化する。
- 採用アイコンの公開利用方針。現在の図柄に含む第三者のマークについて、公開時の扱いを確認する。
- 初版の対象 Windows バージョン・キーボードの確認範囲と既知の制限。
- 署名の有無をリリース説明へ明記する。初版から自動更新やインストーラーは必須としない。

README にはダウンロード、展開先を固定して起動する手順、設定、自動起動の解除、終了・削除、対応範囲を記載する。リリースには `CopilotKeyFighter.exe`、README、確定したライセンスを収録し、ビルド中間物は含めない。

## repository-memory の運用

`agent-knowledge/entries/` と生成済み `INDEX.md` を用意する。未実装の計画はこの文書で管理し、検証済みの知識として登録しない。移植と回帰検証後、修飾キーの安全性、前面化の成立条件、常駐の起動元に関する再利用価値のある事実を、それぞれ独立した記憶として審査する。

既存 AGENTS.md は存在しないため、この初期化だけを目的として新規作成しない。記憶を更新したらスキル付属の validator と indexer を実行する。
